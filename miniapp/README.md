# 微信小程序 · 阶段 B / C 本地实现

独立 Taro 4.2.1 / React 18 / TypeScript 工程。网站继续使用自己的 React 19；本目录独立 workspace 与 lockfile，避免两端依赖互相覆盖。

## 本地编译

在本目录运行 `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm typecheck`、`pnpm build`。
编译时通过环境变量 `MINI_API_ORIGIN` 指定真实 HTTPS API 域名（只包含协议与域名，不带路径、查询参数或凭证）。未配置时仍可编译，但客户端只显示配置提示，不连接示例服务。
输出为 `dist/`。微信开发者工具导入本目录，填写自己的 AppID；私有工具设置不要提交。请求和图片域名需在微信平台配置。后台 AppID/API 域名用于配置记录与检查，不会远程改变已经编译的可信服务地址；变更服务域名需要重新构建客户端。

## 当前能力

- 读取后台已发布配置；原配置的导航顺序、文字、图标动态呈现，关闭导航时回到首页。
- 首页轮播、指定推荐商品；商品/文章/积分商品列表、分类、关键词与 SPU 检索、分页、只读详情。
- 内容必须已发布且明确勾选小程序渠道；历史内容默认不进入小程序。网站渠道独立控制。
- 图片预览与电话悬浮入口，最多 3 个；按页面过滤与键盘避让。离线配置不保留可操作悬浮入口。
- 首页轮播、图片热区、底部导航和悬浮入口均可链接首页、商品、文章、积分商品、购物车、视频页或沙龙会页；链接只允许后台已发布的公开内容。

## 阶段 C 与线下交易

- 个人中心支持已有账号邮箱登录、微信登录和显式绑定，订单/积分及收货地址。
- 后台“小程序—基础配置”配置登录 AppID/AppSecret，密钥在身份服务加密保存；必须与工程 AppID 相同。
- 原生表单支持字段与图片上传，复用网站的校验及积分补偿。
- 详情页选择规格与地址后可兑换积分商品或创建线下付款订单；订单页上传凭证并提交审核，也支持取消、确认收货。线上支付没有伪成功回调。
- 应用迁移 `drizzle/0012_order_channel_guard.sql` 后再进行业务验收，保护并发期间渠道限制。
- 当前网站/小程序现金开关不自动启用。微信支付仅已实现服务端安全基础函数，预支付、通知核销、关单、退款和对账尚待接通，因此不可启用。

## 验收边界

本地单元测试、类型检查、Taro 编译与网站构建通过，不能代替微信开发者工具和 iPhone/Android 真机验收。工程编译 AppID/API 域名需自行核对，未上传小程序、未部署生产、未改正式业务数据。

## 使用已有小程序测试

1. 准备独立测试环境的 HTTPS 接口域名，运行网站、身份服务及数据库迁移；手机不能用电脑 localhost。后台填写登录 AppID/AppSecret 并保存，工程连接记录填相同 AppID 和测试域名。密钥只填后台，不进入源码或命令。
2. 微信公众平台为测试域名设置 request、uploadFile、downloadFile 合法域名（素材不同域名时也需对应配置）。
3. 在项目根目录运行 `MINI_API_ORIGIN=https://你的测试域名 pnpm --dir miniapp build`；本 UAT 的编译值为 `https://aition.art`。
4. 微信开发者工具导入本项目的 miniapp 目录，使用已有小程序 AppID；miniprogramRoot 为 dist/。构建目录不要误选网站根目录。
5. 后台内容开启小程序渠道；补齐装修、保存并发布配置，然后开发者工具编译。配置发布和微信正式版本发布不是同一动作。
6. 用该小程序的开发者微信扫码预览/真机调试。依次测试首页热区/轮播/导航、公开详情分享、游客浏览、信任登录、头像昵称、手机号授权、地址、购物车、线下订单、表单、积分兑换、视频与沙龙；分别在 iPhone、Android、Wi-Fi 与移动网络记录结果。微信在线支付尚不能验收。
7. 不需要提交微信审核或发布正式版本即可先做开发预览。本轮没有代为上传任何版本。
